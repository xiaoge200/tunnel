## 它能做什么

假设你的数据库跑在跳板机后面的内网 `192.168.1.50:3306`,平时只能用 SSH 登录跳板机访问。Tunnel 帮你:

```
本地数据库客户端  ──►  127.0.0.1:15432   (Tunnel 在本机监听)
                         │
                     SSH 加密隧道(经跳板机)
                         │
                     192.168.1.50:3306   (目标内网服务)
```

- **多台主机并行连接**,各自独立启停;单台故障不影响其他隧道
- 迷你悬浮面板逐行显示每台隧道的**实时状态与上下行速率**,可直接启停
- 配置面板集中管理(增删改 + 全部连接/全部停止)
- 密码加密落盘;关闭窗口自动隐藏到托盘,后台持续转发

> 支持平台:**仅 Windows 10/11 x64**(macOS / Linux 暂未支持)

## 快速上手(3 步)

### 第 1 步:添加隧道

1. 点击悬浮面板右上角 **⚙** 打开配置窗口(或托盘右键 → 配置)
2. 点击 **[+ 添加隧道]**,填写:

| 字段 | 说明 | 示例 |
|---|---|---|
| 隧道名称 | 便于识别的名字 | `生产库跳板` |
| SSH 主机 | 跳板机地址 | `106.54.242.26` |
| 端口 | SSH 端口 | `22` |
| 用户 | SSH 登录用户 | `root` |
| 认证方式 | 密码 或 私钥 | 密码:`******` |
| 端口转发规则 | 见下文 [详解](#端口转发规则详解) | 见示例 |

3. 点击 **💾 保存**,回到列表,新隧道出现在卡片列表中

### 第 2 步:启动隧道

任选一种方式:

- 配置窗口列表卡片上的 **[▶ 启动]**
- 悬浮面板对应行的 **[▶ 启动]** 按钮
- 托盘右键菜单,点击该隧道条目

状态会依次变为 连接中(黄,闪烁)→ 已连接(绿)。若失败,卡片上会**内联显示红色错误原因**,把光标放在红字上可看完整信息。

### 第 3 步:使用

把本地数据库客户端/工具的连接地址填成 `127.0.0.1` + 你在转发规则里设置的**本地端口**即可,效果等同于直连目标服务:

```
MySQL:  127.0.0.1:15432   用户/密码照常
psql:   psql -h 127.0.0.1 -p 15432 ...
ssh:    ssh -p 15432 ...
```

> 首次使用前建议先用 `Test-NetConnection 127.0.0.1 -Port 15432`(PowerShell)或 `telnet 127.0.0.1 15432` 确认本机端口已在监听。

## 界面与操作指南

### 迷你状态面板(桌面悬浮窗)

```
┌────────────────────────────────┐
│ TUNNEL                    ⚙ ✕ │   ← 按住空白处可拖动;⚙ 打开配置;✕ 隐藏到托盘
├────────────────────────────────┤
│ ● 已连接  生产库跳板     [⏹] │
│   已连接 ▼ 12KB/s ▲ 3KB/s      │
│ ○ 未连接  测试环境       [▶] │
│   未连接 ▼ 0B/s   ▲ 0B/s       │
└────────────────────────────────┘
```

- 每行:状态点 + 隧道名 + 状态文字 + 实时下行/上行速率 + 启停按钮
- 窗口高度随隧道数量自动伸缩(上限内滚动)
- 关闭窗口 = 隐藏到托盘,**程序不退**,转发不中断

### 配置窗口(集中管理)

- **列表页**:每张卡片显示 名称 / `用户@主机:端口` / 转发条数 / 状态徽章;按钮:启动 · 停止 · 编辑 · 删除(删除前有确认对话框;删除正在运行的隧道会自动先断开)
- 顶部工具栏:[+ 添加隧道] [▶ 全部连接] [⏹ 全部停止]
- **编辑页**:修改后点 💾 保存;运行中的隧道不受编辑影响,配置在**下次启动该隧道时生效**;[← 返回列表] 放弃修改

### 托盘(系统通知区)

- **图标 = 应用 logo,颜色表示整体状态**(见下表);左键单击唤出悬浮面板
- **右键菜单**:每台隧道一行(带实时状态标记,点击即启动/停止它)+ 全部连接 / 全部断开 / 配置 / 退出

## 状态颜色说明

| 状态 | 面板/菜单显示 | 托盘 logo 颜色 | 含义 |
|---|---|---|---|
| 未连接 | 灰 ● 未连接 | 灰蓝 | 未启动 |
| 连接中 | 黄 ◐ 连接中(闪烁) | 黄 | 正在建立 SSH 连接 |
| 已连接 | 绿 ● 已连接 | 绿 | 转发正常工作中 |
| 错误 | 红 ● 错误 | 红 | 连接失败/断开,原因见卡片红字 |

托盘图标取**汇总色**:有任一错误 → 红;否则有任一连接中 → 黄;全部已连接 → 绿;其余 → 灰蓝。

## 端口转发规则详解

一台隧道可配置**多条转发规则**,每条 = 一个本地端口对远端一个地址的映射:

```
本地端口(本机)  →  目标主机:目标端口(经 SSH 服务器视角可达)
   15432            192.168.1.50:3306
   15433            127.0.0.1:5432    ← 目标也可以是跳板机自己
```

- **目标主机**:以跳板机为视角解析的地址——内网 IP、`127.0.0.1`(跳板机自身)、内网域名均可
- **本地端口**:监听在本机的端口;避免多条隧道/多条规则重复使用同一本地端口
- 添加/删除规则用转发区右侧的 **[+ 添加]** 与行末 ✕

## 安装

在 [Releases](../../releases) 页下载最新安装包(如 `Tunnel_x.x.x_x64-setup.exe`),双击安装即可,无需额外环境。

前置要求(Windows):

```bash
git clone <仓库地址>

npm install

npm run tauri build   # 构建安装包
```

产物路径:`src-tauri/target/release/bundle/nsis/*.exe`

## 配置与安全

- 配置文件:`%APPDATA%\com.xiaoge.tunnel\tunnel.json`(单机所有隧道)
- SSH 密码使用 **AES-256-GCM 加密**后落盘,不存明文;但解密密钥编译在程序内部,**属于防误读的混淆级保护**,不是硬件级安全——请勿在不可信环境存放重要凭据,退出登录后建议手动清理该文件
- 私钥文件按路径明文保存,请确保私钥文件本身权限受控
- 当前版本**不对服务器主机密钥做指纹校验**(信任首次连接的任何主机),请仅在可信网络中使用

## 常见问题 FAQ

**Q:一直"连接中",最后变红?**
A:单次连接超时 15 秒。请检查:主机地址与端口是否可达(云服务器安全组/防火墙是否放行 22)、DNS 是否正确、跳板机是否真的允许该用户登录。

**Q:提示认证失败(Password authentication failed)?**
A:密码错误,或该服务器**禁用了密码登录**——请改用"私钥"认证并上传公钥到服务器 `~/.ssh/authorized_keys`。

**Q:私钥导入失败?**
A:请使用 OpenSSH / PEM 格式私钥(如 `id_rsa`、`id_ed25519`);用编辑页的 [浏览] 按钮选择文件以免路径转义出错。注意:**带口令(passphrase)的私钥暂不支持**,请使用无口令副本。

**Q:启动成功但连不上 127.0.0.1:端口?**
A:检查该"本地端口"是否被其他程序占用(Tunnel 只监听未占用端口,冲突时仅记日志不提示);换一个本地端口重试。另外确认目标服务真的在监听 `目标主机:目标端口`。

**Q:修改配置后看起来没生效?**
A:运行中的隧道不受编辑影响——先 [⏹ 停止] 再 [▶ 启动] 即可。

**Q:重启程序后所有隧道都显示"未连接"?**
A:正常现象:隧道状态不持久化,重启后需手动重新连接(托盘"全部连接"一键搞定)。

**Q:点了 ✕ / 关闭悬浮窗,程序还在吗?**
A:在,只是隐藏到托盘(托盘图标还在)。彻底退出请用托盘菜单 → 退出。

**Q:想反馈 Bug 或提需求?**
A:欢迎到 [Issues](../../issues) 提交,请附上场景与日志。

```
├── index.html            两个窗口共用的页面骨架(视图按窗口标签切换)
```
